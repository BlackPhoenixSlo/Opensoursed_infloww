# Messages Pro parity

Graded at `fe3011c8`

What Inflowwww adds on top of Infloww's Messages Pro, where each addition sits, and how close each Region is to Infloww. The parent effort (messages-pro-parity) first graded this doc at `3126cbdd`, by hand, from each Phase's sign-off result (tickets 13, 82, 62, 105, 101, 41, 24 and 120, and Phase 7's sign-off, ticket 127, under `.scratch/messages-pro-parity/issues/`), every `VISUAL GAP:` line of that effort, the Not wired controls each Phase recorded, and the "—" fields Phase 5 shows. The look-and-feel effort (tickets 131–152 under `.scratch/messages-pro-look-and-feel/issues/`) regraded it at `fe3011c8`, the commit where ticket 151's Visual loop fixes landed; nothing under `app/`, `scripts/` or `service/` changed after it. The evidence for this regrade is the Compare page `docs/screenshots/messages-pro-compare.md`, re-pinned to the same commit, with every visible difference as a Compare row (ID, Clone px, ours, owning ticket, Status), and the `VISUAL GAP:` lines of tickets 131–151. Extras come from the catalogue `app/lib/openinflowwwwExtras.ts` (`EXTRAS`), so the doc and the code agree. Specs: `docs/spec/phase-07-ours-kept-marked.md` and `docs/spec/messages-pro-look-and-feel/phase-06-sign-off.md`.

## How Regions are graded

- **Reference.** The Clone (`ui-redesign/infloww-exact/messages.html`, `messages.js`; deleted in cleanup Phase 2, tag `legacy-ui-final`), except where an ADR or newer evidence overrides it. Where a Compare row marks the real Infloww capture "(wins)", the capture's value is the reference (Phase 0's Clone px rule). The Pop-out window is graded against ADR-0002 (a full Messages Pro), not the Clone's one-Thread pop-out (`messages.html:85`). For Fan insights, the newer help-centre evidence in `docs/infloww-screens.md` §3.3 beats the Clone.
- **Colour.** Colour is graded against the Infloww palette, per ADR-0010: since ticket 133 Messages Pro draws in Infloww's palette (`InflowwPalette`), and the Compare page's colour rows CO1–CO7 must all read `matched`; they do, each backed by a harness colour check in `docs/screenshots/messages-pro-report.json`. A remaining colour difference is a `differs` Compare row and is named in its Region's row as a hex value, reference beside ours.
- **Light theme.** As Phase 1 settled it: under `html[data-theme="light"]` Messages Pro shows the same Infloww dark palette as under the dark theme, with `color-scheme: dark` (harness checks "same colours under data-theme=light"), and the App accent stays purple outside Messages Pro. Light-theme Infloww values are not graded.
- **Typography is not graded by the shots.** The harness refuses the font download, so every shot renders in `'Sora Fallback'` (`docs/ui-shots.md`). A font difference is a Visual loop read, never a matched row by default.
- **`done`**: every Clone element in the owning Phase's Gap table is present, that Phase's acceptance checks passed, its result lists no `VISUAL GAP:`, Not wired control or "—" field for the Region, and no Compare row for the Region reads `differs`. A `done` row's Ours cell never names an unwired control or a visual gap.
- **`partial`**: anything short of done, including a failed or skipped acceptance check. The Ours cell names each missing thing and the ticket that recorded it. It also cites every `differs` Compare row of the Region by its ID, with the reference value beside ours (px for Geometry, the hex value for colour) and the owning ticket. A Region that no `differs` Compare row names reads "no px difference remains", which means exactly that: no `differs` Compare row names the Region. Any px or colour difference carried from the parent grade that never became a Compare row is then named beside the phrase with the reference value, ours and its ticket, and a `differs` row graded under another Region is cited by its ID with that Region named.
- **`ours-only`**: Infloww has no counterpart. Never used for a Region that is missing an Infloww element.
- **Evidence.** Each Clone evidence cell names the Clone's lines and the Region's Compare rows on the Compare page.
- An open `ASSUMPTION:` line in a Phase spec does not by itself make its Region partial.
- A `VISUAL GAP:` line that says a state appears in no shot still counts. Those lines are marked "test-only (Decision G)" below, after the parent plan's 2026-10-14 Decision G (no new harness states).
- A vetoable ticket that landed counts like any other. A vetoed Part C (TH7–TH9) would leave its rows `differs`, and the Message list would read `partial` with them named.

## Ours

Every Inflowwww extra's tooltip starts with "Inflowwww extra — <name>". Automation extras render only with the Legacy flag on. Fan insights is the exception since 2026-10-21: every extra there shows by default, with no "+" and no flag (ADR-0003's amendment). The Fan List too since 2026-10-26: it has no Extras overflow, and Owe reply and the extra sort orders are in plain view (ADR-0003, amended 2026-10-26). Every other extra sits in its Region's Extras overflow, named "Inflowwww extras", in both flag states unless the bullet says otherwise. Since ticket 140 the Chat header's Extras overflow is the last row of the Kebab menu, "Inflowwww extras ▸", which opens it as a submenu; the Composer has had no Extras overflow since TODO A2 (`docs/messages-pro-feedback-2026-10-16.md` A2), its extras sitting where the bullets below put them.

- **Persona button** — Chat header Kebab menu; behind the Legacy flag; a "Persona" row in the "Inflowwww extras ▸" submenu (no longer an ⓘ after Find, ticket 140) that opens the Creator's read-only Persona card (local time, activity, bio, location, schedule).
- **Scheduled chip** — Chat header; in the Chat header Extras overflow, the Kebab menu's "Inflowwww extras ▸" submenu; the "🕐 N" count of direct sends queued for this Fan, shown only when one is queued.
- **Owe reply** — Fan List; since 2026-10-26 a chip right after All, its count always in the amber corner badge; filters the Fan List to the Fans who wrote last and are owed a reply.
- **Broadcast** — Fan List; behind the Legacy flag; the last item of the "New" menu behind the "+" at the right end of the Fan List header's first row, a link to the Nudge Online tab of the automations page (`/automations?ready=nudge_online`).
- **Group chat** — Window header and Chat header; in the Window header Extras overflow with the flag off and first in the Fan tabs row with the flag on, plus a second entry point in the Chat header Extras overflow (the Kebab menu's submenu) in both flag states; adds this Fan's Thread to the Group chat tab, up to eight Threads side by side.
- **Free previews** — Composer; since TODO A2 inline in the PPV row whenever media is attached; the "previews − N/M +" stepper that sets how many of a PPV's attachments the Fan sees free, enabled only with a price and an attachment, while its free-preview divider tile shows in the PPV row, the fourth row between the input and row 3 (ticket 148).
- **All Models** — Window header; in the Window header Extras overflow with the flag off and in the Window header itself, after Home, with the flag on; one Fan List that spans every Creator.
- **Generated profile note** — Fan insights; shown by default since 2026-10-21 (once behind the Legacy flag); the AI profile filled by gen_info, in the Notes tab.
- **Persona claims** — Fan insights; shown by default since 2026-10-21 (once behind the Legacy flag); the claims block of the chat engines' prompts, in the Notes tab.
- **Automation restrict** — Chat header Kebab menu; behind the Legacy flag, after the Infloww Kebab rows and the message statistics rows, before "Inflowwww extras ▸"; "Auto-restricted" and "Restrict from automations" / "Allow automations" put the Fan on or off the automation skip list.
- **Mass exclude** — Chat header and Fan insights; in the Chat header Extras overflow (the Kebab menu's submenu) and, since 2026-10-21, as Fan insights' Mass exclude block; the one MASSdmEXCLUDE switch keeps the Fan out of every mass send, priced or not (MASSppvEXCLUDE was merged into it 2026-10-21), and the manual Mass message composer pre-ticks that list.
- **Mark as unread** — Chat header; in the Chat header Extras overflow, the Kebab menu's submenu; deletes the chat's read mark so the Fan shows as unread again.
- **Phone focus** — Chat header; in the Chat header Extras overflow, the Kebab menu's submenu, shown below lg only; strips the Chat header down for the phone, and the kebab stays visible in focus mode so focus can be turned off.
- **Quick emojis** — Composer; since TODO A2 in Composer row 1, after ⚙; a one-tap emoji row that inserts into the draft.
- **At presets** — Composer; since TODO A2 under ⏱, in its "Send at presets" group; +5, +10, +15, +30 and +60 min fill "at" and turn on schedule mode without sending.
- **Fan identity** — Fan insights; since 2026-10-21 the Fan block on the Insights tab; the Fan's avatar, name, @username and Creator label · id.
- **Unsold PPVs** — Fan insights; since 2026-10-21 the Unsold PPVs sent block on the Insights tab, shown with none too; PPVs sent to the Fan and not bought, each with "Send to chat".
- **Extra sort orders** — Fan List; since 2026-10-26 in the sort menu of the sort icon button beside the gear, under its "Sort by" head; Amount spent, Spend + unread on top and Spend + recency, one entry per order, while the sort button's title names the active order ("Sort: <order>").
