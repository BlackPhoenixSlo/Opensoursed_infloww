# Keep running pre-empts only the Kept promo, and only on numbers OnlyFans gave

**Status: proposed** (2026-11-19, `goal_promo_preempt.txt` Phase 01; nothing built yet).

PR #850 stands down whenever any promo is live (the fix for a ping-pong between two armed campaigns), so a filled Claim cap leaves the profile with no offer from the last claim until the next look, about 2 min and longer while OnlyFans lags. We decided Keep running may Re-create while the Kept promo is still live (Pre-emption), relying on OnlyFans ending the old promo when a new one is created, under four limits: it acts only when the Live promo's id is the Kept campaign's current `of_promo_id` (any other live promo, by hand or from another campaign, still means stand down); Fill pre-emption only on a Trusted count at or above 90 % of a Claim cap of 10 or more (below 10, 90 % rounds to full, so those use After-end re-create only); Timed pre-emption only on the OF end time, never on created + finish days; and the After-end re-create stays as the fallback. The second tick, Re-create at 90% filled, is ticked by default. We chose this because it closes the gap without any new OF call: the decision rides the Subscribe toast Pokes, Re-checks and Backstop already counted in PR #850, and the price check reads only the cached subscription price (`account_page`, ≤ 6 h), never a fresh `/users/me`. The safeguards ship first as their own slice, so After-end alone is safe before Pre-emption's switch (`PROMO_PREEMPT_ENABLED`, off) is flipped. The trade-off: a Pre-emption on a wrong number publicly ends a promo that still had room and starts another, which could repeat, so every input is OnlyFans's own and any doubt means wait for the After-end path. That OnlyFans ends the old promo on create (and what happens if the create fails) is inferred from the ping-pong incident note in `promo_reactivate.py`, not measured; if the owner-test-account measurement shows otherwise, Pre-emption stays off. Fill pre-emption hands out 90 % of each cap, so about 11 % more creates for the same Claims (arithmetic). Going back means retiring the second tick and the trust checks; the profile's promo history keeps every extra promo made.

## Considered Options

- **Keep the stand-down, re-check sooner.** Rejected: the gap stays, and a faster look is more OF calls.
- **Poll claims on a timer.** Rejected: breaks the "request counts unchanged" goal.
- **Pre-empt on our guessed end time.** Rejected: a guess or clock skew ends a live promo early.
