# An explicit unknown Platform key refuses loudly, and Shim markers carry Platform-neutral names

**Status: accepted** (2026-11-27, `.scratch/multi-platform-p2/plan.md` Phase 02a; tickets 09, 11; markers and the Unknown platform built in 02a-1, the app's "Unknown platform" row lands in 02d).

ADR-0053 left an unknown `meta.platform` on OnlyFans, and measurement shows what that costs: an explicit unregistered key reaches the OnlyFans client pool with no refusal (`platforms.py:46-56`, `automation_executor.py:438-442`) and counts as OnlyFans in the app (`app/lib/platform.ts:29-34`), while a second Shim copying the Fansly-named markers as `<site>_unsupported` would classify as built (`side_effect_gate.py:15-19`) and a `returns=lambda: {"success": True}` stand-in reports ok. We decided the Shim markers are `platform_unsupported`, `platform_blocked` and `platform_live_check`, with no success stand-in; the Platform-key scan is built from the registry; `platforms.get` keeps a missing or `None` key as OnlyFans (legacy meta) but turns a non-empty unregistered key into `UnknownPlatform`, so dispatch refuses with `platform_unknown:` and loads no client and the app shows "Unknown platform" with no gated controls; account writes validate the key before any early return or credential file write; and a test-only dummy third key must fail the Drift test and a new check that every non-OnlyFans registry row has a Backend module. We chose this because the destination is a third Platform that fails in tests instead of silently riding the OnlyFans path, and only a loud refusal makes a wrong key visible. The cost: a Creator stored with a mistyped key stops running until it is fixed (no prod meta is known to carry one; the `platform_refusals` WATCH check alerts on `platform_unknown:`). This overturns ADR-0053's unknown-key ASSUMPTION for explicit keys only.

## Considered Options

- **Keep the OnlyFans fallback for every unknown key (ADR-0053).** Rejected: a non-OnlyFans session would be driven by the OnlyFans client with no error.
- **A neutral error base class for Shim errors.** Rejected: nothing catches the Fansly classes, and `server.py` already maps any Backend API error by status.
- **A generic login contract, `/admin/session/{key}` route or scaffold script now.** Parked: the body depends on site #2's capture, and the Platform recipe is the checklist.
