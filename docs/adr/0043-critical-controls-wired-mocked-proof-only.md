# Critical controls are wired but proven only by a Mocked proof

**Status: proposed** (2026-11-20, `docs/plans/ofm-not-yet.md` Phase 5; nothing built yet). Amended 2026-11-20 in plan review (decisions D2, D12): the off-by-default switch and the mocked-proof class.

Every other Not-yet control gets a Live proof on the Proof Creator (ADR-0042), but for a Critical control (Bank payments, cards, payout types, DAC7 and support; the Statements support form; OF settings account password, username, email, phone, 2FA passwordless and delete) a live write would withdraw money, file tax or payout data, write to OnlyFans support, change the owner's sign-in or delete his account: none can be undone, and a sign-in change can lock the owner out of his own Creator. We decided Critical controls are wired the same way as the rest (Request capture, Relay route, binder, `data-oi-wired`), but behind one Relay switch, `OF_CRITICAL_CONTROLS`, read from the Relay's environment, off unless it is exactly `1`, and usable only by the owner's own session; while it is off (the default on every Deployment) each keeps its Not-yet title and sends nothing. Their only proof is a Mocked proof: the binder sends the captured shape to a mocked Relay and nothing reaches OnlyFans. The Request capture of a Critical control never lets its request reach OnlyFans either. No run sends one live, and any live use waits for the owner's own go, outside this effort. We chose this because the owner's goal is that every not-yet control works, while the plan's hard limits forbid a real withdrawal, bank, payout or DAC7 submit, a real password, email or phone change, and Delete account. The cost: the first time OnlyFans sees one of these bodies from Inflowwww is an Agency's real use, where a wrong body fails on a real account. Its body being OnlyFans's own output, never a guess (ADR-0005), is what limits that risk. A wired Critical control is live only on a Deployment where the owner has set the switch. The same mocked-proof class also holds the writes that have no undo: Report, Create new release form, Create new invitation link, Close all sessions, Reset stream key, Unlock post and Send tip. They are wired and Mocked-proven, and keep the Not-yet title until the owner names one in a go and its Live proof passes (Phase 0's `--owner-go`), or the switch covers it; a go never lifts the Relay's `_denied` backstop, which is its own owner-go change.
ASSUMPTION: a Critical control's Request capture is read from OnlyFans's own JS, or taken in the browser with the request intercepted and aborted before it leaves (rung 4, from the hard limits); overturned if the owner supplies a capture another way.
ASSUMPTION: the plan's "ask the owner first" gates any live use of a Critical control, not its wiring (rung 5); overturned if the owner meant no wiring before his go, which parks Phase 5.
ASSUMPTION: Critical controls are wired, not left on onlyfans.com (the plan's Phase 5 scope, rung 2), though the plan's open question asks the owner whether to skip Bank and account security entirely; overturned if he answers skip, which means never setting the switch, so these controls keep the Not-yet title.

## Considered Options

- **Leave them on onlyfans.com.** The plan's open question to the owner; not taken because the plan's Phase 5 wires them.
- **A live proof with a harmless value** (the same password, a $0 change). Rejected: it is still a real submit, which can set off OnlyFans's security mail or 2FA, and the plan forbids it.
- **Always on once wired** (title dropped, live for every Agency), this ADR's first text. Replaced by the switch: it put Critical controls in every Agency's hands before the owner's go.
- **A per-Agency or `runtime_switches` toggle.** Rejected: a copied database could turn Critical controls on for a second host (ADR-0041's env-not-DB reasoning), and one Deployment-wide switch answers the owner's question.
- **Undo-less writes treated as Lockout controls** (proven live, then reverted). Rejected: Close all sessions, a report or a tip cannot be reverted, so a Live proof of one is only ever an owner-named go.
