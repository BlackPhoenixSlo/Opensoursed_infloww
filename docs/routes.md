# Routes

The sidebar, settings tabs and stub pages are all driven by one tree in
`app/lib/nav.ts`. Labels are verbatim from `docs/infloww-screens.md` §1.1 / §3.10;
routes follow §2. "Stub" = renders the shared `components/NotBuiltYet` empty state.
"Owner" = hidden from chatter-only sessions (`chatterHidden`).
Grades for each route against Infloww (Matrix status, remaining gap) are in
`docs/infloww-parity-matrix.md`.

## Responsive behaviour

- **Sidebar** (`components/shell/AppShell.tsx`): fixed at `lg` (1024px) and up, except on Messages Pro, where it is the off-canvas drawer at every width; below `lg` it is an off-canvas drawer (Radix Dialog, `#app-sidebar-drawer`) opened by the top bar's "Toggle sidebar" button. It closes on route change, Escape or a backdrop click, and traps focus while open.
- **Top bar** (`components/shell/TopBar.tsx`): below `lg` the timezone and the "SFW" label are hidden (the toggle stays); below `sm` the Inflowwww wordmark is hidden too.
- **Messages Pro** below `lg` shows one pane at a time: chat list -> thread (header "Back" returns to the list) -> "Fan insights" slide-over. The account roster is hidden; scope switching lives in the top bar. `lg` and up keep the three-pane grid. On `/messages-pro` the help bubble only shows from `lg` so it stays clear of the composer. A Pop-out window (`?window=1`) has no top bar and no drawer, and is still one pane at a time below `lg`.
- **Heights**: chat surfaces use `.h-chat` (`--vvh`, which follows `visualViewport` and falls back to `100dvh`) so the composer stays above the iOS keyboard. The composer pads by `env(safe-area-inset-bottom)`.
- **Tables** scroll inside their own `overflow-x-auto` container; the page itself never scrolls sideways (`body { overflow-x: hidden }`).
- **Viewport** (`app/layout.tsx`): `viewportFit: "cover"` and `themeColor: "#14151a"`.

## Relay: OF Manager Statistics reads and Fans writes

Relay routes (`service/server.py`) the Statistics pages can call. Each one is mapped to Statistics in `service/permissions.py` `PAGE_MAP`, so a role that holds only Statistics may call it and any other role gets a 403. Item ids go in the query or body, never the path: a path such as `/posts/{id}` is owned by other pages' routes. Paths and params come from OF's web bundle (`app.js` module ids below). OF's response body is returned unchanged. Tests: `service/tests/test_statistics_reads.py`, `test_statistics_writes.py`, `test_role_enforcement.py`.

The Statements payout lists, mapped to Statements: GET `/api/of/v2/payouts/requests` and `/api/of/v2/payouts/requests/referral` take `limit` (10, 1..50) and `offset` as before, plus optional `start`, `end` and `marker`, sent to OF as `startDate`, `endDate` and `marker` the way OF's own pages page them (app.js 977600 `se` / `re`). Without them the request is unchanged. OF answers `{list, marker}`, with no `hasMore`.

GET `/api/of/v2/payouts/download-approved-invoice?invoiceId&isRefbonus` (mapped to Statistics) returns OF's invoice PDF: OF answers 200 `application/pdf` with an attachment `Content-Disposition` carrying its own file name, which the relay passes on with `Cache-Control: no-store`. Any other reply, whether an error or a body that is not a PDF, is a 502 `{"detail": {"upstream_status": <OF status>}}`. The upstream URL is never returned or logged.
